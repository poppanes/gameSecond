用户新增需求：除石头/箱子外，加"墙"地形，类似空气墙，可在编辑地图时添加使用。

  - `parseLevelLayout` 支持 `#`→walls、坐标数组 `walls`，返回 `{stones, boxes, walls}`
  - 文件头注释更新字符约定
- **`map.js`**：
  - 构造函数加 `wallGrid`；`hasWall(col,row)` 方法
  - `applyLayout` 支持 walls 落位（越界/禁区/石头箱子重叠校验）
  - `canMoveTo`/`pushBox` 加墙不可通行；`flipLine` 四方向扫描加墙阻挡
  - `areAllFlipped` 豁免墙格；`initEmpty` 清空 wallGrid

  - `_canPass` 加 `map.hasWall()`（所有寻路/移动/传送自动避开墙）
  - flying 撞障碍处加 `map.hasWall()`

### 关键点
- 怪物移动统一走 `_canPass`，所以墙自动对所有怪生效（含 Owl 传送）
- 玩家移动走 `canMoveTo`，推箱子走 `pushBox`，都已拦截
- `_buildForbiddenSet()` 含四角出生点+相邻格+玩家起点，墙放禁区会被 applyLayout 跳过并告警

## 黑洞布局禁区收紧（用户案例："最右边两个H无法生效"）
用户报告：第 11 关写 `"....HHHH"`（黑洞在 (4,1)(5,1)(6,1)(7,1)），右边两个不显示。

### 根因
`_buildForbiddenSet()` 默认包含「角落出生点+相邻格+玩家起点」。`(7,0)` 的相邻是 `(6,0)(7,1)`，所以 `(7,1)` 和 `(6,1)` 都在禁区。同理 `(7,6)` 的相邻 `(7,5)(6,6)` 也算禁区 → `(7,5)` 被跳过。黑洞本来怪就进不去，没必要把角落相邻格也禁。

### 修复
- `_buildForbiddenSet(includeBirthNeighbors=true)`：新增参数，false 时不包含角落相邻格
- `applyLayout`：
  - 石头/箱子用 `forbidden`（默认含相邻格）——保护怪出生点不被堵死
  - 墙/黑洞用 `blockedForbidden`（不含相邻格）——怪本来就进不去，可紧贴角落
- 但放置后仍 `forbidden.add(key)` 防止黑洞墙之间互相重叠

### 验证
用户 id:11 布局 `"....HHHH"` (row 1/5) 现在 4 个黑洞全部生效（之前最右 1~2 个被禁区跳掉）。

## 角色移动顿挫修复 + FPS 显示
用户反馈：角色移动一格一格不顺畅，要求改为流畅移动并显示当前帧数。

### 根因
移动是 **keydown 事件驱动 + 150ms 节流**：
1. keydown 触发一次 → 走一格
2. 走完 isMoving=false，但要等浏览器/OS **key repeat**（300~500ms）才再次触发
3. 再叠加 `moveDelay=150ms` 节流
→ 每格之间有几百毫秒空档，产生顿挫感

### 修复（改为每帧状态驱动）
- **`input.js`（GameInput 重写）**：
  - 移除 `moveDelay`/`lastMoveTime` 节流
  - 新增 `pressedDirs` 方向栈（后按优先）、`_codeToDir(code)` 按键→方向向量
  - 新增 `update()`：每帧检测，若不在移动中且有按住方向 → 立即 move 下一格
  - `onKeyDown` 方向键入栈 + 立即响应；新增 `onKeyUp` 出栈
  - `updatePlayer` 清空 pressedDirs（换关/重开）
  - 撞墙时 `_lastMoveTry` 50ms 冷却，避免每帧调 pushBox 刷日志
- **`game.js`**：
  - loop 里 `this.update(dt)` **之后**调用 `gameInput.update()`（本帧走完立即续下一格）
  - 新增 `SHOW_FPS` 常量（默认 true）、`fps`/`_fpsFrames`/`_fpsTimer` 状态、FPS 统计（每 500ms 刷新）、`drawFps()` 左上角绘制（>=55绿 / >=30黄 / 否则红）
  - render 最前面调用 drawFps（所有模式都显示）
- **`player.js`**：`moveSpeed` 0.35 → 0.45（88px/格 约 195ms，更跟手）

### 说明
- 匀速插值，连续移动视觉上是匀速直线，无中间停顿
- 移动完成与下一格启动间隔 1 帧（16ms），不可感知
- 菜单/测试/结束态按键逻辑不受影响

### 二次优化：转向加速（消除转向延迟）
上一版遗留问题：移动中按新方向要等当前格走完（最多 ~195ms）才转向，不够跟手。

方案：**转向时本格加速走完**（不是瞬移，位置仍连续，无跳变）
- **`player.js`**：
  - `moveSpeed` 0.45 → 0.55（88px/格 ≈ 160ms）
  - 新增 `boost`（加速倍率）、`lastMoveDir`（上次移动方向）
  - `update()`：`const step = Math.min(this.moveSpeed * this.boost * dt, dist)`；本格结束时 `boost = 1`
  - `_commitMove()`：`boost = 1`（新格正常速度起步）
  - `move()`：记录 `lastMoveDir = {dx, dy}`
  - `respawn()`：重置 `boost = 1`
- **`input.js`**：
  - 顶部常量 `TURN_BOOST = 3`
  - `update()` 增加 `if (this.player.isMoving)` 分支：比较 `lastMoveDir` 与按住方向，不同则 `player.boost = TURN_BOOST`，否则 `boost = 1`
- **`map.js`** pushBox 推玩家处：`player.boost = 1`

### 效果
转向延迟从「剩余整格时间」降到约 1/3（~50ms 内），且位置连续无跳变。
调参：`TURN_BOOST`（input.js，1=关闭加速）、`moveSpeed`（player.js，建议 0.45~0.7）

## 怪物穿墙 BUG 修复
用户报告：墙本质同黑洞，怪物/玩家/箱子均不可穿。但怪物能穿墙。

### 根因
各怪物子类的移动/寻路**没有复用 `_canPass`**，而是各自直接判断 `hasStone`/`hasBox`/`isBlackHole`，漏了 `hasWall`。基类 `findPath` 的 `_canPass` 已含墙，但子类自定义移动逻辑绕过了它。

### 修复（enemy.js，6 处全部补 `hasWall`）
1. Spider 随机移动 valid 过滤（单行）
2. Snowman 正常态随机移动 valid 过滤（单行，与 Spider 相同文本，replace_all 一起改）
3. Snowman `_findFlippedTarget` BFS：`hasStone||hasBox` → `||hasWall`
4. Snowman `_bfsStep` BFS 可通行：加 `&&!map.hasWall`
5. Octopus 追踪/随机移动：`hasStone || isBlackHole` → `|| map.hasWall`
6. Owl 随机移动 valid 过滤（两行版）
7. Ghost `_bfsNearestFlipped` BFS：加 `|| map.hasWall`

### 说明
- Ghost 狂暴态/Snowman 狂暴态走 `findPath`（_canPass 已含墙），本就正确
- Owl 传送走 `_canPass`，本就正确
- Ghost `_scanRow`/`_scanCol`/`_findTarget`/`_flipCurrentAndAdjacent` 只找翻转目标（不直接移动），墙格 tile 恒白不会被翻，无需加墙

### 待办
- 用户需在 levels.js 各关 layout 里加 `#` 来布置墙（当前示例 layout 尚未加墙）
- 上线若需真空气墙：`WALL_VISIBLE = false`

## 黑洞 BUG 修复（推箱子进黑洞 + 玩家顺势进入）
用户报告：Owl 制造黑洞后，玩家可推箱子入黑洞，并顺着箱子进入黑洞格（应禁止）。

### 根因
1. `map.pushBox` 没检查"目标格是黑洞"——箱子直接落进黑洞格
2. `player.move` 走"推箱子分支"时，`_commitMove` 前**没**复用 `canMoveTo` 的黑洞判定——箱子被消除/移走后，玩家顺势 `_commitMove` 进入黑洞格

### 修复（双重保险）
- **`map.js` pushBox**：在石头检查前加 `if (typeof isBlackHole === 'function' && isBlackHole(newRow, newCol)) return false`——箱子推不进黑洞
- **`player.js` move**：`pushBox` 之后、`_commitMove` 之前再校验一次黑洞——即使箱子消失后目标格变黑洞，玩家也不能顺势进入

### 测试地图按键（改为「先选工具，再鼠标点击放置」）
用户追加需求：希望按对应键后，用鼠标点击格子来生成/清除，便于精确复现 BUG 场景。

- 数字 1-5：选怪物工具（Ghost/Spider/Snowman/Octopus/Owl）
- Q=石头  E=箱子  R=墙  T=黑洞  C=清物件  G=清怪物
- 选中工具后 → 鼠标点击地图格子 → 在点击处放置/清除
- Esc/Backspace = 返回菜单
- 实现：`_testTool` 存当前工具；`_bindTestCanvas`(仅一次绑定 canvas click) → `_onTestCanvasClick`(client坐标→canvas坐标→网格) → `_applyTestTool(col,row)`
- `drawTestLabel` 顶部显示"工具: xxx（点击格子放置）"
- `TEST_TOOL_NAMES` 常量（game.js 顶部）映射工具中文名
- `drawTestHelp()`：测试地图底部绘制三行按键说明（怪物/物件/其他），render testMode 分支调用
